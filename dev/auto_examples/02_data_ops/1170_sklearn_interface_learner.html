Turn a DataOp into a “standard” scikit-learn estimator#

When our DataOp only needs 2 inputs, X and y, we can get a learner that accepts the usual scikit-learn inputs rather than a dictionary like SkrubLearners normally do, by using SkrubLearner.with_sklearn_interface() to obtain the learner wrapped in a XySkrubLearner.

import skrub
from skrub import selectors as s
from sklearn.preprocessing import OrdinalEncoder
from sklearn.ensemble import HistGradientBoostingRegressor

dataset = skrub.datasets.fetch_employee_salaries()

Creating an example DataOp#

We define a DataOp that does transformations similar to the TableVectorizer.

X = skrub.var("X").skb.apply(skrub.Cleaner())
num = X.skb.select(s.numeric()).skb.set_name("num").skb.apply("passthrough")
low_card = (
    X.skb.select(s.string() & s.cardinality_below(30))
    .skb.set_name("low_card")
    .skb.apply(OrdinalEncoder())
)
high_card = (
    X.skb.select(s.string() - s.cardinality_below(30))
    .skb.set_name("high_card")
    .skb.apply(
        skrub.StringEncoder(
            n_components=skrub.choose_int(10, 20, n_steps=3, name="n_components")
        )
    )
)
datetime = (
    X.skb.select(s.any_date()).skb.set_name("datetime").skb.apply(skrub.DatetimeEncoder())
)
feat = num.skb.concat([low_card, high_card, datetime], axis=1)
feat


Creating & using the scikit-learn estimator#

Now we make a learner and ask for the sklearn-like interface. It is used as tv.fit_transform(X) (whereas the default .skb.make_learner() behavior would require tv.fit_transform({'X': X})). On any skrub learner calling SkrubLearner.with_sklearn_interface() returns such an estimator that executes the same DataOp but exposes the scikit-learn (X, y) interface instead of the skrub one (which accepts a dictionary).

tv = feat.skb.make_learner().with_sklearn_interface()
tv

interaction_cst interaction_cst: {"pairwise", "no_interactions"} or sequence of lists/tuples/sets of int, default=None

Specify interaction constraints, the sets of features which can
interact with each other in child node splits.

Each item specifies the set of feature indices that are allowed
to interact with each other. If there are more features than
specified in these constraints, they are treated as if they were
specified as an additional set.

The strings "pairwise" and "no_interactions" are shorthands for
allowing only pairwise or no interactions, respectively.

For instance, with 5 features in total, `interaction_cst=[{0, 1}]`
is equivalent to `interaction_cst=[{0, 1}, {2, 3, 4}]`,
and specifies that each branch of a tree will either only split
on features 0 and 1 or only split on features 2, 3 and 4.

See :ref:`this example<ice-vs-pdp>` on how to use `interaction_cst`.

Using the estimator in another DataOp#

As our table vectorizer is a normal scikit-learn estimator, it can easily be used with .skb.apply().

pred = (
    skrub.X()
    .skb.apply(tv)
    .skb.set_name("table_vectorizer")
    .skb.apply(HistGradientBoostingRegressor(), y=skrub.y())
)
